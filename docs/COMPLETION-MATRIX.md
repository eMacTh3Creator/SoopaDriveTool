# SoopaDriveTool implementation and qualification

This ledger describes the 0.3.0 storage suite. Every listed interface has an implemented backend. Qualification records use disposable VMs and disks; device-specific limits remain enforced by the engine. See [validation](VALIDATION-0.3.0.md) for test scope and release receipts.

| Area | Implemented backend and interface | Current acceptance |
|---|---|---|
| Protected backup | AES-256-GCM/Brotli packets, encrypted manifests, full/incremental/differential generations, exclusions, locking, retention/GC, selective restore, passphrase rotation, permissions/streams/hardlinks/links, native VSS requester, DPAPI user/SYSTEM scheduling and management | 53 core checks, 78 focused Windows VSS checks and real metadata restore checks pass. An installed SYSTEM task created an encrypted VSS backup on authenticated SMB; restore preserved file content, streams, owner and DACL. Enable/disable, upgrade retention and uninstall task removal passed. |
| Disk images | Protected compressed chunked raw images, incremental/differential points, verification and read-back restore; VSS Windows WIM capture; raw read-only VHD browsing and selective WIM extraction | Encrypted raw capture → overwrite → restore passed full read-back in the spare VM. Native WinPE raw restore passed an independent complete-disk hash comparison. Unicode read-only VHD browse passed. A protected full Windows image restored through WinPE and independently cold-booted twice with its source/repository disks absent. |
| Migration | Inactive and live VSS Windows UEFI clone, filesystem clone, byte-exact clone, larger-target GPT relocation, fresh OS-aware identifiers, offline drive mapping, EFI/BCD and WinRE registration | Inactive Windows and byte clones have independent boot evidence. A live 256 GiB Windows source cloned to a smaller 192 GiB disk and independently booted twice under Secure Boot. Protected Windows-image restoration also passed two sole-disk cold boots; automatic WinRE activation, service removal and second-boot helper cleanup passed. |
| Partitioning | Real overlap-safe move with durable pending chunks and reviewed resume; split/merge; shrink/move/grow redistribution; filesystem/allocation-unit migration using verified recovery WIM; nonempty GPT/MBR and primary/logical conversion; guarded basic/dynamic simple-volume conversion | Core move fault injection and 85 advanced Windows checks pass. Actual NTFS move, nonempty GPT/MBR, primary/logical, split/merge/redistribution, filesystem/allocation-unit migrations preserve representable content and metadata. Basic → dynamic → basic conversion preserved NTFS files and named streams after restart (80 preparation / 74 post-restart checks). |
| Recovery | Backup GPT reconstruction, lost NTFS/exFAT/FAT32 partition scan and reviewed insertion, NTFS deleted MFT/data runs, FAT32 deleted directory entries, contiguous PNG/JPEG/PDF carving, source-byte preview/export, hash-guarded sector editor | Core recovery bounds, nonoverlap, retained original sector, stale preview, carving/export and surface checks pass. An actual deleted NTFS MFT record and data runs were recovered in the advanced Windows suite. Fragmented carving, compressed/EFS NTFS recovery and multi-disk dynamic reconstruction are outside supported modes. |
| Diagnostics and erase | Full exported SMART/logs; device self-test requests; temperature samples/chart; read surface map/report; volume/pool/virtual-disk topology; free-space overwrite; Windows native NVMe erase; WinPE ATA erase with direct-bus, frozen/locked/security checks | Full SMART parsing/export and actual VM device-output retention pass; an unsupported firmware self-test was explicitly rejected. Real free-space overwrite preserved allocated files; surface timing, topology and VM firmware-erase guards pass. One-pass/random/three-pass disk overwrites pass full read-back. Firmware erase requires an eligible disposable physical device for hardware qualification. |
| Recovery media | Native ARM64/x64 host, authenticated raw restore, Windows WIM apply/boot reconstruction, byte clone and verified overwrite; installed-ADK ISO/USB builder and signed-driver injection | Native ARM64/x64 hosts compile and execute archive compatibility checks. An ARM64 ADK/WinPE ISO booted under Secure Boot; native GUI raw restore and full Windows-image restore passed, including independent destination boots. The final release ISO and native hosts passed damaged-EFI repair, full data/login checks, WinRE activation, two independent Secure Boot cold boots and repeated-helper cleanup while preserving an unrelated pending rename. Physical USB boot and x64 recovery boots need hardware qualification. Microsoft boot files are not bundled in public installers. |
| Benchmarking | Standard and custom block/queue/thread/read-percent workloads; random/zero data, profile save/load, exports, historical throughput comparison charts, device temperature history | Actual native standard/custom DiskSpd workloads, cancellation and cleanup pass. Saved-profile serialization, run comparison and temperature history are implemented; virtual-machine throughput is not physical-drive performance evidence. |
| Usability | Task tabs, disk maps, apply queue, measured/indeterminate activity, waiting facts toggle, journals and interrupted-run detection, light/dark/system themes, compact layout, labeled input controls | All 10 primary workspaces render; light/dark overview and benchmark renders were visually checked. Actual queue execution records current phases, completed/pending steps and verified outcomes. Controls have input labels; complete assistive-technology/high-DPI qualification remains outside the current test scope. Interface instructions are English. |
| Release | Native components and licenses integrated into package build; ARM64/x64 installers and portable packages | Final ARM64/x64 CI and package publication receipts are recorded with the release. The 0.2.1 → 0.3.0 upgrade preserved 35 history files, preferences, a legacy backup and a DPAPI SYSTEM job; that job ran after upgrade and uninstall removed its task. Builds are unsigned. |

Supported conversions and recovery modes enforce their filesystem/device constraints before writing. A submitted SMART self-test is not a health pass, a controller erase completion is not a certified purge, and a captured Windows image is not considered boot-qualified until the restored disk is independently booted.
